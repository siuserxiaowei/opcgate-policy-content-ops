# 从“政策很多”到“我该去哪”：重做 OPC Gate 的一次产品纠偏

## 一、第一版为什么不对

我最初拥有的是一批 OPC 政策和载体数据。为了贴近“AI + 运营”赛题，第一版被做成了政策内容运营助手：输入话题、匹配政策、生成分层草稿。

它能运行，也有边界，但我重新问了一遍最初的问题：一个创业者打开 OPC Gate，真正想完成什么？

答案不是“写一篇政策内容”，而是：

> 我想做一人公司，应该选哪个 OPC 空间，为什么，下一步怎么申请？

如果产品把这个具体动作变成抽象的内容工作流，即使功能完整，也偏离了真实需求。因此我没有继续提交旧定位，而是把比赛版重做为 **OPC Gate 空间匹配与申请助手**。

## 二、它仍然是一款运营工具

用户侧的动作是选空间；运营侧解决的却是园区招商和创业服务里的重复劳动：

- 反复回答“我的项目适合哪里”；
- 从不完整描述中判断行业、阶段和服务需求；
- 把咨询分流给合适载体；
- 让创业者在咨询前准备基本材料；
- 区分介绍页面、政策来源和真实申请入口。

因此产品同时服务两个角色：创业者得到清晰候选，园区运营得到信息更完整的预筛线索。

## 三、产品工作流

```text
城市 + 行业 + 项目阶段 + 所需服务
  → 同城载体硬筛选
  → 行业 / 阶段 / 服务需求可解释排序
  → 空间匹配护照
  → 选择 2–3 个候选比较
  → 按阶段生成申请材料清单
  → 打开明确的公开入口，或联系运营方核验
```

默认演示案例是：

> 广州 + AI / 大模型 + 已有 Demo + 需要低成本工位、算力 / Token 和融资路演。

系统会优先推荐琶洲模方 SOPC 加速器，并明确展示它与 AI、工位、算力和融资需求的对应关系。换成“跨境 / 出海 + 注册政务 + 跨境服务”后，南沙国际 OPC 生态社区会排到第一。

## 四、为什么不用一个黑盒分数

每个结果都是一张“空间匹配护照”，固定回答三个问题：

1. 为什么适合：命中了哪些行业与服务信息；
2. 证据是否完整：载体来源是否已核验；
3. 下一步是什么：存在公开线上入口，还是需要联系运营方。

排序分数只帮助用户缩小候选范围，不代表入驻资格、获批概率或官方推荐。真正重要的是推荐理由能被用户读懂、被运营人员复核。

## 五、申请入口是最容易“看起来完整、实际上造假”的地方

数据中的 `source` 通常是载体介绍或政策页面，不一定是申请页。为了让 Demo 看起来闭环，最容易犯的错误是把所有来源都包装成“立即申请”。

比赛版采用了更保守的规则：只有载体特征中明确写出“线上入口 / 申请入口”的公共 URL，才显示“打开公开入口”。其他有来源的载体显示“准备申请 / 联系运营方”；没有来源的显示“联系运营方 / 核验入口”。

这意味着界面不一定处处都有漂亮按钮，但不会把一个介绍页伪装成申请入口。

## 六、数据与证据状态

作品复用 OPC Gate 的公开数据快照：

- 128 个 OPC 载体，覆盖 38 个城市；
- 119 个载体有地址；
- 126 个载体关联政策；
- 53 个载体有已核验介绍来源；
- 125 条政策作为推荐解释的辅助证据；
- 数据快照日期为 2026-05-22。

资料并不均匀。缺少可靠来源的载体不会被隐藏，但会显示“信息待核验”，让数据缺口成为产品状态，而不是被文案掩盖。

## 七、测试驱动的重做

这次先写失败测试，再实现新版逻辑。测试覆盖：

- 城市是同城硬筛选；
- 行业、阶段和服务需求会改变排序；
- 广州 AI 默认案例优先推荐琶洲模方；
- 跨境 / 注册案例优先推荐南沙国际 OPC；
- 每条结果都有推荐理由、地址、运营方、服务特征、证据和入口状态；
- 没有来源时绝不生成虚假入口；
- 只能比较 2–3 个空间；
- 申请清单会随项目阶段变化；
- 空条件、无结果和失效比较项有明确反馈。

核心 `app.py` 测试覆盖率为 82%，Python 新版测试与既有 JavaScript 回归测试全部通过。随后又在桌面和 390×844 手机视口跑通完整流程，并检查页面没有横向溢出。

## 八、界面为什么叫“匹配护照”

新版不再用政策大屏和统计卡片作为主角，而是借用园区导览、地址牌和申请档案的语言。首屏唯一重点是填写需求；结果以护照形式呈现地址、运营方、理由、证据和下一步。

视觉上使用图纸蓝、档案纸、导视绿和印章棕。颜色不是装饰：绿色表示可继续行动，棕色表示资料仍需核验。

## 九、既有基础与本届新增

OPC Gate 的政策导航、数据集和领域方法早于本届比赛存在，所以我没有把整个项目包装成活动期从零开发。

本届活动期内新增的是：空间需求画像、可解释推荐、园区招商分流、匹配护照、2–3 项比较、申请材料清单、公开入口边界、ModelScope 创空间版本、响应式界面、测试与提交材料。

## 十、下一步验证什么

当前没有真实用户量、转化率或节省时长，因此不预先制造漂亮数字。下一步会观察：

1. 创业者能否在 60 秒内选出 2–3 个候选；
2. 推荐理由是否足以支持第一次咨询；
3. 园区运营收到的项目描述是否更完整；
4. 从搜索到找到真实入口需要多少次跳转；
5. 哪些城市和载体最需要补齐公开来源。

这次纠偏让我确认了一件事：AI 产品不应该为了符合一个抽象类别而远离原始问题。把“我该去哪”回答清楚，比再多做一个内容生成流程更重要。
